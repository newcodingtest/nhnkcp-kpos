## < 과제 : 주문 시스템 설계 및 구현 >

- 기술 태그
    - Java 17 이상, Spring Boot 3 이상,  JPA, Maven, H2 Database, QueryDSL, 그 외 필요시 추가 가능

- 요구사항
    1. 상품
        - 상품은 다음 정보를 포함해야 합니다.
            - 상품명, 가격, 재고수량, 카테고리
        - 상품은 카테고리별로 분류되며, 특정 카테고리의 상품 목록을 조회할 수 있어야 합니다.
        - 상품은 등록, 수정, 조회가 가능해야 합니다.
        - 재고 수량이 부족한 경우 주문은 실패해야 합니다.

    2. 주문
        - 주문은 하나 이상의 상품을 포함할 수 있습니다.
        - 주문은 다음 상태를 가질 수 있습니다. (대기, 접수, 완료, 취소)
        - 주문 생성 시 기본 상태는 대기 상태입니다.
        - 주문 상태는 생성 이후 변경할 수 있어야 하며, 비즈니스적으로 올바르지 않은 상태 변경은 허용되지 않아야 합니다.
        - 주문이 완료가 되면 주문에 포함된 상품들의 재고가 차감되어야 합니다.
        - 주문이 취소될 경우 주문에 포함된 상품들의 재고는 복구되어야 합니다.

- 기능
    1. 상품
        - 상품 등록, 상품 수정, 상품 단건 조회, 상품 목록 조회, 카테고리 기준 조회, 페이징 처리

    2. 주문
        - 주문 생성, 주문 상태 변경, 주문 단건 조회, 주문 목록 조회, 주문 상태별 조회, 기간별 조회

- 과제 내용
    1. 설계 및 구현
        - 주어진 요구사항을 기반으로 백엔드 시스템을 설계하고 구현하세요.
        - H2 Database를 사용하여 데이터베이스 모델을 설계하세요.
        - 상품, 주문 도메인에 대해 필요한 RESTFUL API 엔드포인트를 정의하고 구현하세요.
        - 상품 목록 조회, 주문 생성, 주문 상태 변경 등 핵심 기능을 포함해야 합니다.
        - 각 API에 대해 예상되는 요청(Request) 및 응답(Response) 구조를 자유롭게 정의하세요.
        - 도메인 데이터는 정형화 되도록 설계하세요.
        - 유연한 비즈니스 모델링으로 구현하세요.

    2. 데이터 무결성 및 예외 처리
        - 잘못된 요청에 대해 적절한 예외 처리와 일관된 에러 응답을 제공해주세요.
        - 다음과 같은 예외 상황을 반드시 고려해주세요.
            - 존재하지 않는 상품에 대한 주문 요청
            - 재고 수량이 부족한 상품 주문
            - 허용되지 않은 주문 상태 변경 요청
        - 데이터 정합성이 깨지지 않도록 트랜잭션 처리 방안을 고려해주세요.

    3. 동시성 및 트랜잭션 고려

        - 동시성 문제를 어떻게 해결했는지 코드 또는 README에 간단히 설명해주세요.
            - 예시 : 락 사용, 트랜잭션 전략, 기타 접근 방식 등

    4. 테스트
